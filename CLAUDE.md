# CodeCamp Guidelines
This document contains critical information about working with this project. Follow guidelines precisely. If you are ever in doubt, ask the user for additional context or ask leading questions.

## Context 
- 1 week programming course
- Students aged 14-18
- Restricted to using CodeHS platform
- **Beginner**
	- New attendees who have indicated no/low experience with code 
	- Creating websites using HTML, CSS, JS
	- Content available from previous years
- **Advanced**
	- New attendees who have indicated mid/high experience with code, or previous attendees
	- Self-guided tutorials (not taught, not graded) that prepare students for an end-of-week game competition using PyGame
	-  3-4 Brief tutorials, each completable independently in ~6 hours total - this is a budget, not a target to fill; prefer trimming over padding
	- No rubric, autograder, or assessment checklist - these are prep material, not coursework to be marked
	- Assume the general programming fundamentals taught in Beginner (variables, loops, conditionals, functions), but do not assume the student attended Beginner, and do not reference Beginner content or camp history directly. Briefly refresh these concepts as they come up, in their Python/PyGame context
	- New concept, no previous years' content to reference

## Style
- Sections broken into lessons
- Break lessons into small chunks: pair each concept with a short, relevant activity or checkpoint. Match Beginner's granularity and pacing as a formatting model - this is about structure only, not about referencing Beginner content or camp history in the material itself
- Use Markdown files
- Content must be accessible for students of all abilities (within reason - use logical deduction or ask user for context)
- Concise but detailed - use discretion or ask the user to approve if in doubt
- Advanced tutorials are self-guided and ungraded: frame any checklists as student self-checks ("did your game do X?"), not instructor assessment criteria or teacher-facing grading notes
- Lessons should teach concepts through theory, and activities should use tasks or step-by-step tutorials to implement features using these concepts
	- Separated into lesson and tutorial folders


## Other Restrictions
- **Never** commit or create/comment on PRs
- Always ensure lessons or tasks are compatible with CodeHS platform
- Write lessons with reference to using CodeHS. Do not name drop it excessively, but ensure lessons will be suitable for users on this platform specifically.
- **DO NOT** use em-dashes 
- **NEVER** make artifacts - all readmes or summaries should be LOCAL .md files, or printed in chat only.
