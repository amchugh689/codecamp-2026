# Advanced Final Project Rubric: End-of-Week Game Competition

Students are challenged to design and build an original game, applying the Pygame concepts and techniques covered in this week's tutorials (the game loop, drawing, movement, collisions, scoring, and input handling) to a game idea of their own.

## What students were told (brief summary)

Students were told their final project must be an **original game idea**, not a modified or reskinned version of Snake, Pong, the shooter, or Flappy Bird. Reusing techniques from the tutorials (a collision detection function, a scoring system, how they structured their game loop) is expected. What needs to be original is the game itself: its concept, how it plays, and its look and feel.

They were told their game needs:

- A smooth, working game loop and responsive controls
- A clear win, lose, or end condition
- A way to track score or progress
- A way to restart or play again
- Rules simple enough for a new player to understand without it being explained to them

They'll demo their game at the end of the week and explain how it works, the choices they made, and what they'd improve with more time.

**When judging, treat a submission that is a modified or reskinned tutorial game (same core mechanic, just new art or minor tweaks) as not having met the brief, regardless of how polished it is.** Score it against the Beginning or Developing levels for Creativity & Originality below, whatever its technical quality elsewhere.

## Scoring levels

Each criterion is scored against one of four levels: **Beginning**, **Developing**, **Proficient**, **Excellent**. Multiply the level reached by the criterion's weight to get a weighted score out of 100.


| Criterion (weight)                  | Beginning (0-5)                                                                                                                 | Developing (6-10)                                                                                           | Proficient (11-15)                                                                                              | Excellent (16-20)                                                                                                                                |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Core Gameplay & Mechanics** (25%) | Movement or collisions don't work reliably, or the game crashes during normal play.                                             | Core mechanics mostly work but have noticeable bugs (e.g. inconsistent collisions, unresponsive controls).  | Core mechanics work reliably: movement, collisions and controls behave as expected.                             | Core mechanics work reliably and feel responsive and well tuned (good pacing, fair difficulty).                                                  |
| **Game Completeness** (20%)         | No clear win/lose condition or way to end the game.                                                                             | A win/lose condition exists but is inconsistent, or scoring/restart is missing or broken.                   | The game has a clear win/lose condition, working score tracking, and a way to restart or play again.            | The game has a clear win/lose condition, working score tracking, a way to replay, and the rules are obvious to a new player without explanation. |
| **Creativity & Originality** (20%)  | Game is an unchanged copy of a tutorial game, or a reskin with only cosmetic changes (new colours, sprites, or theme) and the same core mechanic. | Game borrows a tutorial game's core mechanic with some mechanical changes, but isn't a genuinely different concept. | Game is an original concept, clearly distinct from the tutorial games, built using techniques learned this week. | Game has a distinctive original concept that goes clearly beyond the tutorials, showing thoughtful, well realised design ideas of the student's own. |
| **Code Quality** (15%)              | Code is hard to follow (no functions, unclear naming, everything crammed together).                                             | Code uses some functions or structure but is inconsistent or hard to follow in places.                      | Code is organised into sensible functions with reasonably clear naming.                                         | Code is well organised into functions, clearly named, and easy for someone else to follow and extend.                                            |
| **Polish & Presentation** (10%)     | Game has placeholder or missing visuals/sound, or basic usability issues (e.g. no on-screen feedback for scoring or game over). | Game has some visual/sound elements and basic feedback (e.g. a score display) but feels unfinished.         | Game has consistent visuals and sound, with clear feedback for key events (scoring, game over).                 | Game has consistent, well chosen visuals and sound that make it enjoyable to play, with clear feedback throughout.                               |
| **Demo & Explanation** (10%)        | Student can't explain how their game works or what they built.                                                                  | Student can describe what the game does but struggles to explain how the code achieves it.                  | Student can explain how their game works and describe the choices they made.                                    | Student can clearly explain how their game works, the choices they made, and what they'd improve with more time.                                 |

## Using this rubric

- Pick the level that best matches the entry for each row, even if it's a partial match.
- The weighted score is a guide for ranking entries, not a strict cutoff. Use judgement for borderline cases, and weigh creativity and effort alongside technical polish.
- Feedback to each student should highlight one strength and one specific next step, not just the level reached.
