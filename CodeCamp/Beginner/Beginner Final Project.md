# Code Camp Website Marking Rubric 2026

Students were asked to build a multi-page website on a topic of their own choosing, using everything covered this week. Their brief asked for:

- **At least 3 pages** that link to each other
- **HTML structure** using headers, paragraphs, images, links, and divs
- **CSS styling**, ideally in its own stylesheet, consistent across all pages
- **At least one working piece of JavaScript** that responds to something the user does

They were told the project doesn't need to be fully finished to present it, and that AI tools are fine for learning, debugging, or generating images/placeholder text, but the site needs to be their own work and they'll be asked to explain their code.

**Presentations:**

- Students should present their website in a **3-4 minute demo**, with a demonstration of the website, and a walkthrough of the code.
- Projects do not need to be fully completed.
- Take notes in the notes section of the scoring sheet during the presentations to remember key details.

## Questions to Ask:

- Did you use AI tools to help make your website?
- What was the biggest challenge you faced while creating this website?
- If you had more time, what else would you like to add or improve on your website?

**Code Review:**

- After all presentations, review the code of each project to assess understanding and implementation.

**AI Guidance:**

If students fully generate their projects with AI, it is unfair to those who have learned the material, done extra research, and applied it in their own projects.

It is fine to use AI to generate images, or large quantities of text in circumstances such as generating many product descriptions or large amounts of placeholder text.

If you suspect a project's code is fully AI generated:

- Ask if they used AI tools and how they used them. It is fine to use AI tools, just not to generate the entire website for them.
- Ask to see some of their JavaScript, HTML or CSS code. Ask them to explain how it works.
- When marking, you can check samples of their code in tools such as ZeroGPT. These tools are not fully reliable, but alongside the previous questions and your own intuition you can make a final judgement.
- If you still believe the student has used AI to fully generate their project and has made no meaningful contribution of their own, mark the project as **mostly AI generated** on the scoring sheet and include a short note to explain.

## Scoring levels

Each criterion is scored against one of four levels: **Beginning**, **Developing**, **Proficient**, **Excellent**. Multiply the level reached by the criterion's weight to get a weighted score out of 100.

| Criterion (weight)                | Beginning (0-5)                                                                                                                               | Developing (6-10)                                                                                                                                                                     | Proficient (11-15)                                                                                                                                                                                                      | Excellent (16-20)                                                                                                                                      |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **HTML/CSS Code Structure** (20%) | HTML is missing basic structure tags (`<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`), or CSS is written entirely inline with no stylesheet. | Basic HTML structure is present but semantic elements (`<header>`, `<nav>`, `<main>`, etc.) and divs are missing or used incorrectly, and CSS is a mix of inline and internal styles. | HTML uses semantic elements and divs to structure the page sensibly, and CSS lives in an external stylesheet that's reasonably organised.                                                                               | HTML uses semantic elements and divs thoughtfully to structure a clear page layout, and CSS is well organised in an external stylesheet.               |
| **UI Design** (20%)               | Little or no styling applied, or the site is hard to navigate.                                                                                | Basic styling (colours, fonts, spacing) is applied but looks inconsistent, or navigation is confusing in places.                                                                      | Styling is applied consistently, giving the site a clear visual theme, and it's easy to find your way around.                                                                                                           | Styling is consistent and shows a deliberate design choice, and the site is genuinely easy and pleasant to use.                                        |
| **Functionality** (20%)           | No working JavaScript, and/or the site has fewer than the required 3 pages, or links/pages are broken or disconnected.                        | JavaScript is present but doesn't reliably work as intended, or the site is short of 3 pages, or some links don't connect properly.                                                    | JavaScript adds working interactivity (e.g. form validation, dynamic updates, responding to clicks, query selectors), code is reasonably clean, and the site has at least 3 pages that all link up correctly.           | JavaScript adds working, well organised interactivity that noticeably improves the site, and the site has 3 or more pages that are fully interconnected. |
| **Complexity** (20%)              | No real technical challenge attempted, and no evidence of problem-solving.                                                                    | A simple feature is attempted (e.g. basic toggling) but with little logic behind it, or the student can't describe a problem they solved.                                             | The student has implemented a feature with real logic (e.g. handling user input, calculations, loops, working with forEach or query selectors across a collection of elements), and can describe a problem they solved. | The student has implemented a genuinely complex feature with clear logic, and can clearly explain both the technical challenge and how they solved it. |
| **Creativity** (20%)              | Idea closely copies an example with no personal spin, or the project is mostly AI generated with no meaningful contribution of their own.     | Idea is a safe, generic choice with little originality.                                                                                                                               | Idea and design reflect the student's own thinking, and they can explain their choices.                                                                                                                                 | Idea, design and execution are distinctive, reflecting genuine creative thinking that goes beyond the example prompts.                                 |

**Award 0% for Creativity if a project is judged to be fully AI generated with no meaningful contribution of the student's own (see AI Guidance above).**

## Using this rubric

- Pick the level that best matches the project for each row, even if it's a partial match.
- The weighted score is a guide, not a strict cutoff. Use your judgement for borderline cases.
- Feedback to each student should highlight one strength and one specific next step, not just the level reached.
